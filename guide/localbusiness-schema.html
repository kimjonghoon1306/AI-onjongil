LocalBusiness Schema
작성 가이드
필드 & 업종별 타입

로컬 비즈니스가 AI 검색에서 추천받기 위한 핵심 기술인 LocalBusiness Schema Markup의 필수 필드와 업종별 하위 타입을 Schema.org 공식 명세 기반으로 설명합니다.

온종일AI 편집팀· 2026년 6월 9일· 약 5분 소요

LocalBusiness Schema는 지역 비즈니스(병원, 식당, 학원, 부동산 등)를 AI와 검색 엔진에 알려주는 구조화 데이터입니다. Schema.org에서 정의하고 Google, Bing이 공식으로 지원합니다.

LocalBusiness Schema 핵심 필드

Schema.org의 LocalBusiness 공식 명세(schema.org/LocalBusiness)에 따른 주요 필드입니다.

🏢

name (필수)

업체의 공식 이름. 홈페이지와 Google 비즈니스 프로필의 이름과 일치해야 합니다. NAP(Name-Address-Phone) 일관성의 핵심입니다.

📍

address (필수)

PostalAddress 타입을 사용해 상세 주소를 구조화합니다. addressLocality(시/구), addressRegion(도), postalCode(우편번호), streetAddress(도로명 주소)를 모두 포함합니다.

📞

telephone

E.164 국제 전화번호 형식(+82-2-1234-5678)이 권장됩니다. NAP 정보의 핵심 요소로 AI 검색에서 로컬 비즈니스 인식에 중요합니다.

🌐

url

업체 공식 웹사이트 URL. 검색 엔진이 Schema 정보와 실제 웹사이트를 연결하는 기준점입니다.

⏰

openingHoursSpecification

영업시간을 구조화합니다. dayOfWeek, opens, closes 필드를 사용합니다. AI가 "지금 영업 중인 곳"을 판단하는 데 사용됩니다.

🗺️

geo (GeoCoordinates)

위도(latitude)와 경도(longitude)를 제공합니다. Google Maps와 연동되며 지역 기반 AI 검색에서 정확한 위치 인식에 도움이 됩니다.

JSON-LD 구현 예시

📋 LocalBusiness Schema — 치과 예시 (JSON-LD)

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Dentist",
  "name": "스마일서울치과",
  "url": "https://우리도메인.com",
  "telephone": "+82-2-1234-5678",
  "address": {
    "@type": "PostalAddress",
    "streetAddress": "테헤란로 123",
    "addressLocality": "강남구",
    "addressRegion": "서울",
    "postalCode": "06234",
    "addressCountry": "KR"
  },
  "geo": {
    "@type": "GeoCoordinates",
    "latitude": 37.5012743,
    "longitude": 127.0396597
  },
  "openingHoursSpecification": [
    {
      "@type": "OpeningHoursSpecification",
      "dayOfWeek": ["Monday","Tuesday","Wednesday","Thursday","Friday"],
      "opens": "09:00",
      "closes": "18:00"
    }
  ]
}
</script>

NAP 일관성과 AI 검색

NAP(Name, Address, Phone)는 로컬 SEO와 AI 검색 최적화에서 신뢰도의 핵심 신호입니다. Schema Markup의 NAP 정보가 Google 비즈니스 프로필, 네이버 플레이스, 웹사이트 본문의 연락처 정보와 모두 일치해야 합니다.

✅ NAP 일관성 체크리스트

· Schema Markup의 name = Google 비즈니스 프로필 업체명
· Schema Markup의 address = 웹사이트 푸터/연락처 페이지 주소
· Schema Markup의 telephone = 웹사이트에 표시된 전화번호
· 도로명 주소 표기 방식 통일 (지번 vs 도로명 혼용 주의)

자주 묻는 질문

Q. LocalBusiness Schema를 메인 페이지(index.html)에만 넣으면 되나요?

일반적으로 LocalBusiness Schema는 메인 페이지에 적용하면 충분합니다. 다만 지점이 여러 개인 경우 각 지점 페이지에 별도의 LocalBusiness Schema를 적용하는 것이 좋습니다. 업종별 특화 페이지(예: 임플란트 전용 페이지)에는 Dentist 타입의 Schema를 추가로 적용할 수 있습니다.

Q. Google My Business(비즈니스 프로필)와 LocalBusiness Schema 중 뭐가 더 중요한가요?

두 가지 모두 중요합니다. Google 비즈니스 프로필은 Google Maps와 Google 검색 지도 결과에서 중요하고, LocalBusiness Schema는 검색 엔진과 AI가 웹사이트 자체에서 업체 정보를 인식하는 데 사용됩니다. 두 채널의 NAP 정보가 일치해야 합니다.
